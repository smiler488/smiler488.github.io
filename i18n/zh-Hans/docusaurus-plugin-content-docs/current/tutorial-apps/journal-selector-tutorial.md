## 功能简介

AI 期刊选择器将稿件摘要和投稿偏好与可配置的 26 字段期刊评估模式进行对比。它呈现候选卡片、完整对比表和 CSV 导出。默认的 **Local demo**（本地演示）展示界面；实时推荐使用你选择的 AI 服务商和 API 密钥。

:::caution 非实时期刊数据库
应用不查询 JCR、CAS、Scopus、Crossref 或出版商系统。模型生成的排名、费用、录用率和审稿周期可能缺失、过时或虚构。在投稿之前，请在权威来源上验证每个候选期刊。
:::

## 开始之前

- 准备包含目标、方法、数据和新颖性的摘要；200–400 词是一个实用的起点。
- 收集可选关键词和约束，如 OA 政策、期刊类型、审稿速度或版面费限制。
- 使用 **Local demo** 在不发送数据的情况下检查工作流。
- 实时分析需要网络访问、服务商/模型和你自己的 API 密钥。
- 直接浏览器调用取决于服务商的 CORS 策略。

## 快速流程

1. [打开 AI 期刊选择器](/app/journal-selector)。
2. 在 **Research abstract**（研究摘要）下粘贴稿件 **Abstract**（摘要）。
3. 填写 **Submission profile**（投稿画像）下有用的字段：
   - **Keywords / Focus**（关键词/焦点）
   - **OA requirement**（OA 要求）
   - **Review speed**（审稿速度）
   - **Journal type**（期刊类型）
   - **Suggestions (3–8)**（建议数 3–8）
   - **Special notes**（特别说明）
4. 在 **Journal analysis model**（期刊分析模型）下，保持 Local demo 或选择实时服务商、模型和 API 密钥。
5. 查看 **Indicator reference**（指标参考），如有需要展开 **Review all required indicators**（查看所有必需指标）。
6. 选择 **Generate journal plan**（生成期刊方案）。
7. 查看 **AI summary**（AI 摘要）、候选卡片和完整对比表。
8. 选择 **Download CSV**（下载 CSV）或展开 **View raw AI response**（查看原始 AI 响应）。

## 控件与输出

| 控件或输出               | 用途                                                                                                                       |
| ------------------------ | -------------------------------------------------------------------------------------------------------------------------- |
| **Abstract**             | 实时模式下发送给所选模型的必填稿件文本。                                                                                   |
| **Keywords / Focus**     | 添加主题词或目标范围。                                                                                                     |
| **OA requirement**       | 选择无偏好、要求 OA 或偏好订阅。                                                                                           |
| **Review speed**         | 向提示词添加偏好的审稿周期。                                                                                               |
| **Journal type**         | 选择无偏好、中文核心偏好或 SCI/国际偏好。                                                                                  |
| **Suggestions (3–8)**    | 限制应用处理的模型结果数量。                                                                                               |
| **Special notes**        | 添加合规性、费用或分区偏好等约束。                                                                                         |
| **Indicator reference**  | 显示从[期刊评估文件](https://smiler488.github.io/app/journal-selector/journal-indicator-system.md)加载的模式。               |
| 候选卡片                 | 摘要期刊名称、出版商、IF 领域、JCR/CAS 分区和 OA 类型。                                                                    |
| 完整对比表               | 显示每个返回候选期刊的所有 26 个规范化字段。                                                                               |
| **Download CSV**         | 导出与表格相同的模式和列顺序。                                                                                             |

## 工作原理

应用从静态站点加载期刊评估文件。如果无法加载或解析，它使用页面内置的相同 26 字段默认模式。

提示词包含完整摘要、关键词、投稿偏好、特别说明和指标模式。它要求所选模型返回包含概述和期刊数组的严格 JSON。周围指令以中文编写以对齐模型，而指标文件不翻译地包含在内，大多数输出值以英文请求。

返回的候选期刊限制为所选数量并规范化到所有模式字段。缺失值显示为 `-`；序号在缺失时由本地填充。CSV 列标签为英文，但不保证模型生成的值为英文。以电子表格公式字符开头的值在 CSV 导出时被中和。

Local demo 不发起网络请求，当前返回一个说明性候选期刊，其指标故意未经验证。

## 数据、隐私与外部服务

在实时模式下，完整摘要、关键词、偏好、说明和指标参考被发送到 **Journal analysis model** 中显示的端点。除非服务商及其数据策略适用于你的工作，否则不要提交机密稿件文本。

API 密钥仅保留在当前标签页的内存中，在切换服务商、刷新或离开页面时清除，并发送到所显示的端点。静态站点无法像后端那样保护它。生产环境请使用受限测试密钥和已认证的服务端代理。

服务商 CORS 规则、区域端点、模型访问、账单和配额都会影响直接浏览器请求是否成功。

:::info 时效性字段
当前模式包含 **Impact Factor (2024)** 作为固定字段名。将其视为模式快照，而非值是最新的证明。在出版商和相关索引服务上验证 IF、分区、APC、OA 状态和时间线。
:::

## 局限性

- 界面不强制摘要长度，但服务商上下文限制仍然适用。
- 请求 3–8 个候选数量不保证模型返回那么多有效候选。
- Local demo 为说明性的，仅返回一个候选。
- 应用无法验证期刊是否活跃、被收录、是掠夺性或适合特定机构。
- AI 输出可能不完整，即使缺失字段在 UI 中被规范化。
- CSV 是规划辅助工具，不是当前期刊指标的证据。

## 排障

- **请先粘贴摘要：** Abstract 字段为空。
- **AI 响应无法解析：** 重新生成或选择能可靠返回严格 JSON 的模型。
- **Local demo 中仅出现一个候选：** 这是预期行为；切换到实时服务商进行实际模型请求。
- **许多字段显示短横线：** 模型省略了这些值；不要推断该指标为零。
- **401、403、404 或 429：** 验证服务商、模型 ID、密钥权限、账单和配额。
- **CORS 或网络失败：** 使用 Local demo 或你的已认证后端代理。
- **指标文件不可用：** 应用自动使用其内置的 26 字段模式。
- **CSV 与出版商页面不同：** 以出版商或索引服务为权威，手动更正你的研究记录。
